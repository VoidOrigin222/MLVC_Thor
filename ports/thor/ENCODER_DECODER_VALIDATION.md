# encoder / decoder 总配置验证（2026-10-18）

对外入口统一使用 `encoder`、`decoder`。每端只读取一个 TOML，集中管理五路，
不再需要通过命令选择 `contexts`，也不生成或读取五份临时分路文件。

| 角色 | 可执行文件 | 脚本 | 默认总配置 |
|---|---|---|---|
| 编码 | `bin/encoder` | `scripts/run_encoder.sh` | `configs/encoder.toml` |
| 解码 | `bin/decoder` | `scripts/run_decoder.sh` | `configs/decoder.toml` |

总配置含 `execution`、日志前缀、本端公共参数和五个 `[[streams]]`。先递归合并公共
参数与分路覆盖，再复用原配置校验；五路都通过校验后才初始化 GPU。新文件无需
填写 `mode = "encode"` 或 `mode = "decode"`，角色由程序入口确定。
编解码、量化和接收策略没有改变。旧的单路和五路基准入口继续保留兼容。

## 验证

- 新增 C++ 总配置测试：除默认开启的 UI 统计字段外，十份合并结果与历史 contexts 模板逐字段相等；检查
  pipeline 局部覆盖与继承、错误运行模式、未知字段、错误路数、无效日志前缀、
  无效及重叠的 RTP/RTCP 端口、重复 UI 统计端口。
- 原生 CTest 共 16 项通过；重命名后重新运行总配置测试通过。
- 新增 Python 脚本入口测试，4 项通过，覆盖两个角色的默认配置、自定义配置、
  不存在的文件和多余参数；从其他工作目录执行仍正确切换至运行工作目录。
- 最终入口双板联调：解码先启动，随后启动两静态、两动态、一路实时计时器源，
  最后启动编码；每路 1920×1080、12 FPS、360 帧，五路共 1,800 帧全部编码、
  解码和 RTSP 发布。接收丢包、队列溢出、CRC 错误、依赖缺口、跳帧及发布丢帧均为 0。
- 使用独立测试配置及 RTSP 18554 端口，输出 `/single-out0` 至 `/single-out4`；
  不覆盖正常的 `/ulbvc0` 至 `/ulbvc4`。测试后停止本次启动的源和编解码进程。

本地证据在 `artifacts/one-toml-20261018/`，最终入口测试脚本为
`check_encoder_decoder.py`，每端实际只传入一个总配置路径。该轮验证的是配置入口
及完整帧功能，不重新声称测得新的长测时延峰值；时延结果仍见
[混合场景验证](MIXED_LATENCY_VALIDATION.md)。

启动命令和参数结构见 [总配置说明](MULTI_CONFIG.md)。

五路编码总配置已默认启用 UI 统计，接收地址为 `192.168.5.3`，端口为
39600–39604；测试同时检查统计默认值和重复端口拒绝。UI 计算方式和编码参数未变。
